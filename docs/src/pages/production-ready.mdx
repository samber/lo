# Is `samber/lo` production-ready?

This page exists to answer the question a tech lead or architect asks before approving
a new dependency — with numbers, not adjectives. Every figure below is independently
verifiable at the linked source; none of it is a marketing claim.

12,533 packages depending on `lo` means it's already a transitive dependency of a large

signal of a stable, non-breaking API.

## Versioning policy

`lo` is v1.x and follows [SemVer](https://semver.org) strictly: **no breaking changes
to exported APIs before v2.0.0**, with one explicit exception — packages under `exp/`
(currently `exp/simd`) are experimental and not covered by this guarantee, since they
depend on unstable Go build tags (`GOEXPERIMENT=simd`).

## Dependencies

The core `lo` package has zero dependencies outside the Go standard library. Check
[go.mod](https://github.com/samber/lo/blob/master/go.mod) yourself — the `require`
block there lists test-only dependencies (`testify`, `goleak`) plus
`golang.org/x/text`, used specifically for locale-aware case conversion in the string
helpers (`CamelCase`, `SnakeCase`... with the `WithLanguage` variants). `golang.org/x/text`
is maintained by the Go team as an extended standard library package, not a
third-party dependency in the usual sense.

## Security and licensing

- **License**: MIT — see [LICENSE](https://github.com/samber/lo/blob/master/LICENSE).
- **Vulnerability reporting**: sensitive or security-related issues can be reported
  privately — see the [Community](/community) page.
- **Supply chain**: zero runtime dependencies outside the standard library means zero
  transitive dependency risk from `lo` itself.

## Maintenance

- Actively maintained: commits land regularly (check
  [recent activity](https://github.com/samber/lo/commits/master)).
- 161 contributors, with a concentration on the primary maintainer — typical of a
  focused open-source library, and worth knowing if your organization weighs bus
  factor in dependency approval.
- Packaged for Debian and Ubuntu
  (`golang-github-samber-lo-dev`), which implies independent third-party review and
  packaging by those distributions' maintainers.
